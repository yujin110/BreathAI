# 유사 표현 유형 검증 적용

2026-10-28 로컬 구현. 운영 배포 및 기존 DB 변경은 수행하지 않았다.

## 적용 내용

- 생성 프롬프트에 정상 문장·약어·표기 변형의 예시를 추가하고 최대 10개로 변경했다.
- `services/synonym_validation.py`가 생성 직후와 최종 답변 처리 후 유형을 검증한다.
- `dataset/synonym_policy/v1.json`의 전체 표현 목록에 있는 정상 와이파이 표현은 SYNONYM, 비번 표현은 ABBR로 재분류한다. WiFi는 약어보다는 표기 변형으로 취급한다.
- 등록된 오류형이 해당 군집의 `clusters.csv.text`에서 NFC·양끝 공백 정리 후 전체 일치할 때만 TYPO를 확정한다. 출처 ID는 업로드 내 logId이며 DB 기본키가 아니다.
- 미등록 TYPO, 미등록 ABBR, 잘못된 타입은 검토 보류한다. 빈 값·비문자열·길이 초과·중복은 제외한다. 유사 표현 보류는 FAQ 전체를 실패시키지 않는다.
- 생성 제안은 내부 `_synonymProposals`로 최종 단계까지 보존하며 최종 FAQ 결과에서는 제거한다. 검토 기록에는 원래 제안과 최종 유형, 출처, 교정형, 규칙을 남긴다.
- `synonym_validation.json`에 최종 후보 전체 및 정책의 SHA-256을 기록한다. 콜백은 누락/불일치 시 전송을 거부한다. 같은 내용의 재시도는 가능하지만 결과 또는 정책 변경 시 재검증이 필요하다.
- Docker 이미지와 빌드 컨텍스트에 정책 파일을 포함했다.

## 운영·호환성

외부 콜백과 DB enum은 유지했다. 기존에 생성된 결과는 검증 산출물이 없으므로 그대로 재전송할 수 없다. 파이프라인 최종 단계를 재실행해 검증한 뒤 보내야 한다. 결과 JSON 옆의 해시만 임의로 만드는 방식으로 우회하지 않는다.

보류 항목은 작업별 `dataset/synonym_validation.json`에서 확인한다. 사람이 정책 추가/수정 여부를 판단한 후 새 정책으로 재실행한다. 검토 전용 화면과 API는 추가하지 않았다. 원본 로그·승인된 FAQ·미답변 통계는 변경하지 않는다.

기존 결과의 읽기 전용 검토 명령(보고서 경로는 새 파일이어야 함):

```powershell
python -m services.synonym_validation --data <작업의_dataset_경로> --report <새_보고서.json>
```

이 명령은 제안 유형과 처리 결과를 보고서에 남기며 기존 결과·DB를 갱신하지 않는다. 보고서는 실제 전송 산출물이 아니므로 콜백용 파일로 복사하지 않는다.

## 적용 한계

초기 정책은 보수적이다. 사전에 없는 실제 오타는 자동 확정되지 않으며, 목록을 확대할 때 별도 회귀 검증이 필요하다. 오류 구간은 NFC 문자열의 Unicode 코드 포인트 기준, 끝 제외로 기록한다. 현재 승인 규칙은 전체 표현과 단일 교정 구간을 사용한다.

SYNONYM의 FAQ 의도 적합성은 생성 프롬프트 판단을 유지한다. 전체 표현 목록은 유형을 판정할 뿐 FAQ 연결의 정확성을 증명하지 않는다. 독립적인 의미 검증 모델, 사람 검수 데이터 기반 성능 측정, 보류 항목 UI는 이 구현에 포함되지 않는다. 따라서 명세 전체 구현 완료나 실제 모델의 정밀도 개선 측정 완료를 의미하지 않는다.

급증 키워드의 동사 활용형 추출 문제는 별도이며 수정하지 않았다.
