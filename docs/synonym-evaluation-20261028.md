# 유사 표현 유형 오분류 파일럿 평가

작성일: 2026-10-28 (Asia/Seoul)

## 결론

현재 구현은 근거 없는 TYPO의 자동 확정을 막는 보수적인 차단 장치로 동작한다. 그러나 정상 표현을 올바른 유형으로 복구하고 실제 오타를 인식하는 일반 분류기로서 검증 완료된 상태는 아니다. **오분류 해결 완료 또는 운영 성능 개선 합격으로 판정하지 않는다.**

실제 모델 생성에서 수정 프롬프트도 정상 표현 7항목(중복 포함, 고유 표현 6개)에 TYPO를 붙였다. 검증기는 7항목을 모두 보류했다. 별도 진단에서 검수한 실제 오류형 4개도 모두 보류했으므로, 차단 성공만으로 정확도가 높아졌다고 해석하면 안 된다.

운영 Qwen 7B의 성능 평가는 미완료다. 아래 생성 비교는 **로컬 Qwen2.5-3B-Instruct의 NF4 4비트 탐색 실험**이며, Codex가 표현 형태를 검수했다. 독립적인 사람 정답셋이나 공사 담당자 승인 평가가 아니다.

## 결과 1: 실제 생성 비교

아래 ‘유사 표현 항목’은 유효 JSON이며 tag=FAQ인 결과의 원출력으로 한정한다. JSON 실패나 OUT_OF_SCOPE에서 생성한 표현을 분류 성공으로 세지 않는다. 중복은 항목 수에 포함한다.

| 지표 | 기존 프롬프트 원출력 | 수정 프롬프트 원출력 |
| --- | ---: | ---: |
| 생성 실행 | 12 | 12 |
| JSON 파싱 성공 | 9 | 9 |
| JSON 파싱 실패 | 3 | 3 |
| 토큰 제한으로 잘림 | 0 | 0 |
| 파싱 후 FAQ 후보 | 7 | 7 |
| FAQ 유사 표현 항목 | 62 | 59 |
| 모델이 부여한 TYPO | 0 | 7 |
| 검수상 잘못된 TYPO | 0 | 7 |

따라서 **이번 표본은 프롬프트 변경만으로 오타 오분류가 감소했다는 근거를 제공하지 않는다.** 기존 프롬프트 표본에는 TYPO 출력 자체가 없고, 수정 프롬프트에서 정상 표현에 TYPO가 생겼다. 표본 12개·군집당 1개 seed·3B 양자화 조건이므로 이를 운영 7B의 우열로 일반화할 수도 없다.

수정 프롬프트의 오탐은 다음과 같다.

- 군집 3: `느려` 2회, `느리다`, `느림`, `느려요`
- 군집 11: `더 자세히`, `좀 더 자세히`

모두 정상 단어·활용형 또는 생략 표현이다. 이 목록의 TYPO는 검증 후 정상 유형으로 재분류된 것이 아니라 **REVIEW_REQUIRED로 보류되어 전송 대상에서 빠졌다.**

## 결과 2: 동일한 원출력에 검증기 적용

프롬프트 효과와 검증기 효과를 분리하기 위해 각 원출력에 동일한 정책을 적용했다. ‘기존 프롬프트+새 검증기’는 비교용 조합이며 기존 운영 파이프라인을 실행한 결과가 아니다.

| 처리 | 기존 원출력+검증기 | 수정 원출력+검증기 |
| --- | ---: | ---: |
| 입력 항목 | 62 | 59 |
| 수용 | 35 | 39 |
| 검토 보류 | 14 | 12 |
| 중복 등 제외 | 13 | 8 |
| 항목 유지율 | 56.5% | 66.1% |
| 확정 TYPO | 0 | 0 |
| 수용했으나 추가 콘텐츠 검토가 필요한 항목 | 1 | 3 |

수정 원출력의 보류 12개는 근거 없는 TYPO 7개, 약어 근거 없는 ABBR 2개, 잘못된 enum 3개다. 제외 8개는 중복이다. 항목 유지율은 중복을 포함한 원출력 대비 비율이며 실제 질의 대응률이나 정상 표현 보존율이 아니다.

수용된 표현 39개는 모두 SYNONYM이다. 이 중 불완전한 문구나 부적절한 높임 등 콘텐츠 검토가 필요한 표현 3개도 통과했다. **정상 철자·허용 enum이라는 사실은 FAQ 의도 적합성이나 문장 품질을 보장하지 않는다.**

자동 확정한 TYPO가 없으므로 검증 후 TYPO 정밀도는 100%가 아니라 **계산 불가(N/A)**다. 유효 FAQ 생성 표현에서 검수로 확정한 실제 오타가 없었으므로 생성 표현 내 TYPO 재현율도 N/A다.

## 결과 3: 저장된 실제 표현의 별도 진단

원본 모델 출력과 분리하여, 소스에서 정확히 확인되는 12표현에 TYPO 제안을 인위적으로 넣어 방어 동작을 검사했다. 이 결과는 자연 발생 오분류율에 합산하지 않는다.

| 진단 항목 | 결과 |
| --- | --- |
| 검수상 정상 표현 8개 | 잘못된 TYPO 확정 0개, 정상 유형 자동 복구 0개, 보류 8개 |
| 검수상 실제 오류형 4개 | 올바른 TYPO 확정 0개, 보류 4개 |
| 전체 보류율 | 12/12, 100% |
| 해당 실제 오류형의 자동 확정 재현율 | 0/4, 0% |

검수한 실제 오류형은 `제무재표 → 재무제표`, `내렸오요 → 내렸어요`를 포함한 문장, `미테그 → 미태그`, `너무 시끄러우 요 → 너무 시끄러워요`다. 이 교정은 Codex 검수이며 담당자 확정은 아직 없다.

정책에는 오류·교정 쌍 1개와 정상 표현 7개만 있다. 전체 1,029행에서 이 정책 항목의 정확 일치 사례는 각각 0건이다. 따라서 이번 자료에서 확정 TYPO가 0건인 것은 광범위한 언어 검증 성공이라기보다 **정책 범위가 좁아 확정을 거부하는 구조**와 관련이 있다.

## 추가로 확인한 문제

1. 문장 생략·어미 변화를 TYPO로 보는 오류는 명시적 프롬프트 예시만으로 제거되지 않는다.
2. 정상 문장을 ABBR로 분류하거나 SYNOPYM 등 잘못된 enum을 생성한다.
3. SYNONYM 제안은 기본 수용하므로 부자연스러운 어휘·불완전 문구·의도 불일치를 통과시킬 수 있다.
4. JSON 오류는 두 조건에서 각 3회 발생했다. 파싱 오류를 없었던 것으로 처리하거나 내부 유사어 객체만 추출해 성공으로 세면 평가가 왜곡된다.
5. FAQ 초안에서 부적절한 질문과 근거 없는 답변도 관찰했다. 예시는 `qualitative-findings.json`에 기록했다. 유형 검증 성능을 답변 품질 성능으로 해석해서는 안 된다.

## 운영 7B 평가를 완료하지 못한 이유

- 원격 서버 주소·포트는 `171.235.173.155:34034`로 사용자 확인과 일치했다.
- SSH 상세 로그에서 서버의 공개키 수락을 확인했다. 이후 암호화된 개인키를 비대화형 환경에서 해제하지 못해 서명이 완료되지 않았다. 제 환경에는 연결된 SSH 에이전트가 없었다. 개인키의 암호문구를 채팅으로 받거나 저장하지 않았다.
- 직접 접속과 중계 접속을 모두 확인했다. 팀원의 실패 원인이 동일한지는 확인하지 않았다.
- 로컬에서는 Qwen 7B NF4를 시도했으나 첫 생성이 수분 동안 완료되지 않았고 GPU가 전력·온도 제한을 보고했다. 중단했으며 `synonym-evaluation-20261028/manifest.json`에 품질 결과 없는 중단 시도로 기록했다.
- 서버 접근이 가능해지면 운영과 같은 모델·정밀도 및 해당 업로드를 고정해 다시 평가해야 한다. 3B의 결과를 운영 7B 수치로 대체하지 않는다.

## 후속 보완 우선순위

1. 검토 보류 결과를 운영자가 확인·교정·재처리할 수 있게 연결한다. 보류가 정상 표현의 영구 누락으로 끝나지 않게 한다.
2. 표현의 오류 여부, 약어 여부, FAQ 의도 일치를 각각 검증한다. SYNONYM 제안의 무조건 수용도 보완한다.
3. 이번 평가 자료와 분리한 학습/정책 보완 자료로 사전 및 규칙 범위를 확대하고, 별도 홀드아웃에서 오탐·재현율·보류율·정상 표현 보존율을 함께 평가한다. 이번 표본에 맞춰 사전을 수정한 뒤 같은 표본의 점수를 성능으로 발표하지 않는다.
4. 운영 7B, 반복 seed, 해당 화면의 실제 업로드, 독립적인 사람 검수로 최종 확인한다. JSON 실패와 FAQ 내용 오류도 수용 기준에 포함한다.

이번 작업에서는 평가 스크립트와 산출물만 추가했으며, 결과를 유리하게 만들기 위한 제품 정책 변경이나 운영 배포는 하지 않았다.

## 산출물과 재실행

`deployment-artifacts/synonym-evaluation-3b-20261028/`:

- `manifest.json`, `model-files.json`: 실행 조건·정책·입력/모델 해시
- `inputs/`, `cases.json`, `prompts.json`, `validator-snapshot.py`: 고정 입력과 검증 코드
- `generations.jsonl`: 변경하지 않은 생성 원문 및 초기 실행 기록
- `rescored-generations.jsonl`: 제품 파서와 같은 규칙으로 원문을 재파싱한 평가 기록
- `review-labels.json`, `review-items.json`: Codex의 표현 형태 검수와 항목별 연결
- `observed-review-controls.json`, `control-results.json`: 자연 발생 결과와 분리한 진단
- `qualitative-findings.json`, `summary.json`: 관찰 사례와 집계

초기 평가 파서가 깨진 바깥 JSON에서 내부 객체를 읽는 문제가 발견돼 집계 단계에서 제품과 같은 파싱 규칙으로 모두 재계산했다. 원문을 수선하거나 모델을 재실행해 성공 결과로 대체하지 않았다. 최종 집계는 `rescored-generations.jsonl`과 `summary.json`을 기준으로 한다.

```powershell
python evaluation/evaluate_synonym_types.py --model-size 3B --output <새_결과_폴더>
python evaluation/summarize_synonym_evaluation.py --output <검수_파일이_있는_결과_폴더>
```

생성 스크립트는 현재 작업공간의 로컬 모델 경로를 사용한다. 집계는 정책·군집 파일·검수 파일을 읽으므로 고정 스냅샷과 해시가 일치하는 환경에서 실행해야 한다. 기존 생성 원문을 다시 생성할 필요 없이 집계와 검수 내용을 재확인할 수 있다.
