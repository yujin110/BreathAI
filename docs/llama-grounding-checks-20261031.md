# Llama 근거 준수 진단 — 2026-10-31

## 목적과 범위

Qwen 가중치는 복구·비교용으로 보존한다. 현재 Llama 실행의 필수 의존성은 아니다. 이번 작업에서는 Qwen 가중치·과거 기록·별도 worktree를 삭제하지 않았다.
모델 제거 여부를 판단하기 전에, Llama 3.1 8B Instruct가 명확한 근거 조건을 따르는지 새 통제 입력 5개로 확인했다. 기존 20문항과 답변·점수는 사용하지 않았다.
운영 성능 평가, 대표성 있는 품질 평가, 안정성 부하 시험, 담당자 FAQ 승인율 평가는 아니다.

## 실행 조건

- 모델·리비전: meta-llama/Llama-3.1-8B-Instruct / 0e9e39f249a16976918f6564b8830bc894c89659.
- 로컬 RTX 2060 6GB, NF4 4bit, FP16 계산, 임베딩·출력층 CPU 오프로딩.
- 실제 answer_regenerator / answer_refiner 프롬프트 빌더와 생성 함수를 사용. max_new_tokens=600, temperature=0.3, top_p=0.9, 사례별 seed=42.
- 사례당 생성 1회. 운영 best-of-N 재시도 루프, 자동 Refine gate, 실제 검색기·DB·BE는 실행하지 않음.
- 가상 시설과 합성 근거를 사용. 각 사례의 기대 동작을 생성 전에 파일로 고정.
- 실제 system/user 메시지와 설정·원문·소스 해시를 저장. Judge 점수로 판정하지 않음.
- 아래 검토는 Codex의 출력 대조이며 담당자 승인·독립 전문가 평가는 아님.

## 다음 보완 대상

1. 검색 근거가 없는 경우에는 근거 인용 예시를 넣지 않고, 확인 불가 안내를 분리한다.
2. 실제로 확인되지 않은 고객센터 대응·처리 결과를 약속하지 않도록 안내 정책을 정리한다.
3. 조건별 입력 변형과 반복 생성, 새로운 독립 근거·정답을 사용해 재검증한다.
4. 운영 도메인의 실제 질문과 검증된 정답·근거로 평가를 새로 설계하고 담당자 평가를 받는다.
5. Qwen 제거는 이 검증과 복구 정책이 확정된 이후 판단한다. 파일 보관만으로 현재 Llama 실행에 Qwen이 사용되는 것은 아니다.
