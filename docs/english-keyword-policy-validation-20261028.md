## 변경 동작

`services/keyword_policy.py`와 `dataset/keyword_policy/en_v1.json`에서 영어 정규화, 제외·보호 규칙, 별칭, 축약 부정형을 관리한다. 이 모듈은 표준 라이브러리만 사용한다. 기존 한국어·도메인 불용어 목록은 값 변경 없이 공통 모듈로 이동했다.

`clustering.extract_keywords()`는 로그별 토큰을 군집별로 합산한다. 반복 출현 빈도와 기존 TF-IDF 설정·Top-7을 유지하고 전체/일부 빈 어휘 및 노이즈 군집을 처리한다. 추론 의존성은 해당 기능 호출 때 불러오므로 실제 키워드 함수를 GPU 없이 검증할 수 있다. 원래 문장과 `cluster_docs`는 유지한다.

`dashboard_metrics._burst_keywords()`는 같은 정책으로 후보를 정규화하고 로그별 영어 대표 키 집합으로 매칭한다. 한국어의 기존 부분 일치, 기간, 임계값, 출력 필드는 유지한다. 영어 부분 일치와 별칭 중복 집계를 방지한다.

`run_job()`은 모델 프로세스를 시작하기 전에 애플리케이션 사전을 검증하고 작업 루트의 `keyword_policy.json`에 원본 바이트를 고정한다. 하위 프로세스는 `TTOBAGI_KEYWORD_POLICY_PATH`로 이를 사용한다. 키워드 추출은 작업 dataset의 `keyword_policy_audit.json`에 버전·해시·제외 발생 수·빈 군집 수를 기록한다. 콜백은 스냅샷과 감사 기록이 일치할 때 동일 사전으로 급증을 계산하며 감사 수치를 재가산하지 않는다. 사전 오류는 기존 작업 실패·실패 콜백으로 전달된다.

정책 도입 이전 산출물은 스냅샷과 감사 기록이 모두 없으면 기본 정책으로 콜백을 구성할 수 있다. 감사 기록이 있는 새 작업은 스냅샷 누락·해시 불일치를 오류로 처리한다.

`Dockerfile.ai` 및 `.dockerignore`에 사전 포함 규칙을 추가했다. 사용자의 역할 범위 지정에 따라 FE 안내 변경은 되돌렸으며 이번 AI 브랜치에는 포함하지 않는다. API·DB 계약은 변경하지 않았다.

## 보관 산출물과 재실행

작업공간 `deployment-artifacts/keyword-policy-20261028/`에 다음을 저장했다.

- `unittest.log`: 개별 테스트 결과
- `unittest-summary.json`: 실행 수·실패·오류·건너뜀·Python 버전
- `sample-comparison.json`: 고정 샘플의 기존 후보와 적용 후 후보 비교

일반 Python 환경에서는 저장소 루트에서 필요한 CPU/API 의존성을 설치한 뒤 다음 명령을 사용한다.

```powershell
$env:TTOBAGI_TEST_HTTP = '1'
python -m unittest discover -s tests -v
```

GPU 모델 로딩·임베딩·군집화·FAQ 생성의 실제 전체 실행, GPU 이미지 빌드, 운영 서버 버전 확인 및 배포는 이 기록의 검증 범위에 포함하지 않는다. 배포 시 코드와 사전을 함께 배포하고 필요하면 함께 롤백한다. 완료된 기존 분석 결과를 소급 변경하지 않는다.

## 명세상 유지되는 제한

ver2 11.1절은 초기 제외 목록을 12개로 확정하고 `there`를 임의로 추가하지 않도록 명시한다. 따라서 `There is no WiFi`는 `there`, `no`, `wifi`를 유지하고 `is`만 제외한다. 한국어 `시부터`, `심해서`도 기존 정책대로 유지한다. 팀원이 제보한 이 세 표현을 제거하려면 별도 사전/한국어 정책 변경이 필요하다. 고정 테스트에도 이 범위를 명시했다.
